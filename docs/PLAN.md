# 개발 계획 · 자동 손익 대시보드

> 공개 저장소용 계획서입니다. 과제 원본 데이터와 그 집계값(정답)은 다음 기수도 쓰므로 이 문서와 저장소 어디에도 넣지 않습니다.

## 1. 왜 만드는가

- **배경:** SCM 부트캠프 3차 과제는 Raw data 1,200행을 SUMIFS 로 정비해 전사·본사·폴란드법인 손익계산서, 차트, 인사이트를 만드는 엑셀 과제다.
  멘티 피드백에서 반복되는 실수는 SUM 범위 오류, 합계 칸 이익률을 월 이익률의 합으로 계산하는 것, 누계와 분기 실적의 혼용, 조건부 서식 누락, 인사이트 미도출이다.
- **목적:** 과제가 끝난 뒤 "엑셀 대신 바이브코딩으로 같은 결과를 몇 분 만에 만든다"는 것을 시연한다.
- **결정 사항:**
  1. 빌드 없는 정적 웹(HTML + JS)으로 만들고 GitHub Pages 에 배포한다
  2. 인사이트는 규칙 기반으로 숫자에서 직접 만든다 (API 키 불필요)
  3. 공개 저장소이므로 과제 원본 대신 같은 구조의 가상 데이터를 샘플로 넣는다
  4. 화면은 상단 토글(관점 · 기간) + 탭 5개(요약 · 손익계산서 · 수익성 · 판관비 · 인사이트)

## 2. 입력 사양 (과제 Raw data)

- 열 11개: `손익계산 ID · 거래일시 · 년도 · 월 · 일 · 전표번호 · 대분류 코드 · 중분류 코드 · 소분류 코드 · 회사명 · 금액`
- 회사당 월 50행: 매출 10 · 매출원가 12(3항목 × 4) · 판매관리비 20(5항목 × 4) · 영외수지 8(2항목 × 4)

| 대분류 | 중분류 |
|---|---|
| 매출액 | 매출액 |
| 매출원가 | 제조인건비 · 재료비 · 제조경비 |
| 판매관리비 | 인건비 · 판촉비 · 감가상각비 · 물류비 · 기타판관비 |
| 영외수지 | 영업외수익 · 영업외손실 |

- **손익계산서 20행 양식:** 매출액 → 매출원가(3) → 매출이익 → (매출이익률) → 판매관리비(5) → 영업이익 → (영업이익률) → 영외수지 → 영업외수익 → 영업외손실 → 세전이익 → (세전이익률)
- 영외수지 = 영업외수익 − 영업외손실, 세전이익 = 영업이익 + 영외수지

## 3. 화면 설계

```
┌──────────────────────────────────────────────────────────────┐
│ 자동 손익 대시보드      [파일 올리기] [샘플로 체험] [엑셀로 내보내기] │
│ 관점 (●전사)(본사)(폴란드법인)   기간 [1월]~[12월]   ● 1,200행 정상 │
├──────────────────────────────────────────────────────────────┤
│ 헤드메시지: 인사이트 1위 문장                                     │
├──────────────────────────────────────────────────────────────┤
│ [요약] [손익계산서] [수익성] [판관비] [인사이트]                   │
└──────────────────────────────────────────────────────────────┘
 요약      : KPI 4개 + 월별 매출액·영업이익률(위아래 두 차트) + 손익 폭포차트 + 인사이트 3개
 손익계산서 : 20행 × (합계 + 월/분기) · 단위(원/천원/백만원) · 조건부 강조 · 전사 검산
 수익성    : 법인별 이익률 3종 · 매출 100원의 쓰임새 · 분기 영업이익/이익률 · 원가 항목 비율 추이
 판관비    : 항목 구성 · 월별 누적 추이 · 판관비율 추이 · 항목별 증감표 · 법인별 항목 비율
 인사이트  : 규칙 기반 카드(근거 숫자) + 종합 시사점
```

- 관점 버튼은 데이터의 회사명에서 만든다. 법인이 늘어도 코드를 고치지 않는다.
- 디자인: 무채색 + KPMG 블루(#062F87) 강조, Pretendard, 차트마다 짚는 지점 1~2곳. 금액과 비율을 한 차트의 두 축에 겹치지 않는다.

## 4. 구조

| 파일 | 역할 |
|---|---|
| `js/parser.js` | 시트 선택 · 헤더 자동 탐지 · 정비(빈 행, 텍스트 숫자, 월·날짜 형식) · 점검 리포트 |
| `js/pnl.js` | [회사 × 년월 × 구분 × 항목] 합계 인덱스 → 관점 · 기간별 손익계산서 |
| `js/insights.js` | 규칙 9개 → 점수순 카드 · 헤드메시지 · 종합 시사점 |
| `js/export.js` | SUMIFS 수식이 살아 있는 엑셀 통합문서 |
| `js/charts.js` · `js/app.js` | 차트와 화면 상태 |

- 계산 모듈은 UMD 형태라 브라우저(`file://` 포함)와 node 테스트가 같은 코드를 쓴다.
- 라이브러리는 `vendor/` 에 넣어 오프라인에서도 동작한다. SheetJS 는 npm `xlsx@0.18.5` 의 알려진 취약점을 피해 0.20.3 재배포본을 쓴다.

## 6. 검증 기록

- **계산 대조:** 과제 원본 1,200행을 넣어 전사 · 본사 · 폴란드법인의 매출 · 원가 · 판관비 · 영업이익 · 세전이익을 멘티 엑셀의 SUMIFS 결과와 원 단위까지 대조했다. 전부 일치했다.
  과제 제출본(시트 9개)을 통째로 올려도 Raw data 시트를 스스로 찾았다.
- **엑셀 수식 재계산:** 내보낸 통합문서의 손익계산서 3개 시트 780칸을 수식 계산기(pycel)로 다시 계산했고, 화면 값과 불일치 0건이었다.
- **CSV 반올림 차이:** 엑셀에서 CSV 로 저장하면 소수점 금액이 표시 형식대로 반올림되어 합계가 ±1원 달라질 수 있다. xlsx 로 올리면 원 단위까지 같다.
- **적자월 원인 판정:** 기간 평균과 비교하면 꾸준히 오르는 항목이 원인으로 잡혀, 앞뒤 2개월 평균과 비교하도록 바꿨다.
- **브라우저 검수:** 5개 탭 × 3개 관점 × 1440px · 390px 화면을 자동으로 찍어 확인했다. 콘솔 오류 0건, 가로 넘침 0건.
